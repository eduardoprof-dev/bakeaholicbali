Safe operations

Rules worth remembering

  • “Cancelled” does not automatically mean “refunded.” Check the refund status.
  • Never paste secret API keys into chat, email or screenshots.
  • Do not approve delivery until payment is confirmed and the package is ready.
  • If a webhook fails, fix and replay it—do not ask the customer to pay twice.

                01
                
Start here

                
The Overview is the daily control room. Work from its priority queue first. Use Integrations only when credentials, provider settings or approved WhatsApp template names change.

                
Owner ruleNever edit a secret, callback or template mapping simply to “try something.” Record the old value and reason before every change.

                
              


              

                02
                
Order lifecycle

                
This is the authoritative customer-order sequence. Each step must complete before the next operational action.

                

                  
1CheckoutAddress and delivery quote

                  →
                  
2PaymentXendit confirms paid

                  →
                  
3PrepareStaff packs and prints

                  →
                  
4ApproveAdmin releases delivery

                  →
                  
5DeliverBiteship tracking

                

                
                
    
                  
  • Do not approve delivery before payment is confirmed and the package is ready.
    • 
                  
  • If the website and Xendit disagree, inspect the callback before asking the customer to act.
    • 
                  
  • The Orders page is the operational fallback when WhatsApp actions are unavailable.
    • 
                

              


              

                03
                
WhatsApp messages

                

                  
EventRecipientPurpose

                  
OTP verificationCustomerConfirm phone ownership

                  
Payment receiptCustomerConfirm paid order and open receipt

                  
Admin order alertStaffApprove or cancel a paid order

                  
Shipping updateCustomerCourier and tracking details

                  
Order deliveredCustomerClose the delivery lifecycle

                

                
Template diagnostics belong in Integrations because that is where mappings are changed. Run diagnostics after changing a template name, language, phone ID or access token.

              


              

                04
                
Cancellations and refunds

                
Cancellation changes the order state. Refund changes the money state. They are related but never interchangeable.

                

                  
Cancelled before paymentNo refund is required.

                  
Cancelled after paymentConfirm refund status separately.

                  
QRIS or cardAutomatic refund can be tested.

                  
Virtual accountMay require manual bank payout; do not use for automatic-refund testing.

                

              


              

                05
                
Maintenance schedule

                

                  
DailyPaid orders, delivery issues, failed messages and refund status.

                  
WeeklyLow stock, WhatsApp diagnostics and one receipt/tracking link.

                  
MonthlyCloudflare events, Xendit settlements, account access and backups.

                  
Before releaseTest, review diff, preserve rollback point, deploy, then smoke-test.

                

              


              

                06
                
Developer handover

                
Architecture: Cloudflare → Railway Node server → persistent Railway volume at /app/data. GitHub is the source and release history.

                
node --check server.js
node --check admin.js
node --test server.test.js

                

                  
server.jsPayments, orders, webhooks, WhatsApp and Biteship.

                  
cart.jsCheckout and payment selection.

                  
admin.jsAdmin controls and diagnostics.

                  
invoice.jsReceipts, tracking and printable documents.

                

                
Incident ruleRecord order number and time, compare Admin with the provider dashboard, inspect Railway logs, repair the callback cause, then replay the webhook where supported. Never ask the customer to pay twice.
