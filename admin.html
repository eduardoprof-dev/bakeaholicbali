Integrations

Save your Google Maps, Biteship, Xendit, and WhatsApp Business API credentials here.

These values are stored locally in `order-demo/.env` and applied to the app immediately. WhatsApp template names should match templates already approved in Meta. The admin alert template should accept event, order id, customer name, customer phone, total, payment method, delivery status, invoice URL, and action text. Receipt and shipping templates use dynamic website buttons for receipt/tracking links.

Notification Flow

Current operational behavior for customer and admin WhatsApp messages.

Order created

Customer can receive a pending-payment template if WhatsApp Cloud API and the template are configured.

Xendit paid

Xendit invoice webhook marks the order paid, sends receipt links, and waits for staff approval before delivery is released.

Staff approval

Staff prepares and prints the invoice, then approves delivery. Only then does the app create the Biteship courier request.

Admin alerts

Automated admin WhatsApp alerts use the admin recipient and template from Integrations. Without those, admin watches the orders page and WhatsApp handoff link.

Advanced

Developer map for operational code, webhook routes, and WhatsApp command behavior.

WhatsApp approval

Admin can tap Approve or Cancel from WhatsApp. The app waits 60 seconds and sends an Undo button before creating the Biteship delivery or starting the cancellation/refund flow. Text commands still work: APPROVE, CANCEL, or APPROVE BAK-0001 when several orders are waiting.

Webhook routes

Xendit: /api/xendit/invoice-callback. WhatsApp: /api/whatsapp/webhook. Biteship: /api/biteship/webhook.

Core files

server.js controls payments, Biteship, WhatsApp, orders, and webhooks. cart.js controls checkout. admin.js controls this maintenance console.
